# 行程地图

行程地图 — B/S 浏览器应用

启动
安装 Python 后，在解压目录运行：python -m http.server 8765 --bind 127.0.0.1 --directory dist
然后访问：http://localhost:8765
也可运行包内 start.cmd（请先完整解压，保留 dist 文件夹）。启动器自动打开正确地址；8765 被占用时会选择空闲端口。需要联网加载地图、表格组件及查询服务。

导入与日期
按列名读取 XLSX，可选择一个 Sheet 或全部 Sheet，不自动去重。
年度 Sheet（如 2019、2026）为 5.5 这样的月日补全年份；完整日期使用其自身年份。
按日期、出发时间倒序；无法识别的日期排最后并提示。
如果 Excel 已把数值 5.10 保存为 5.1，无法判断原来是不是 10 日，请使用文本或日期格式。

地图交互
铁路显示为红色半透明线；航空显示为亮银色线，配细暗色描边。
同一对机场的航班使用不同曲率，往返也会错开。
所有航班可点击。铁路按精确起终站名称、不分方向合并计数，往返计 2 次；合计不超过 6 次可点选卡片。
次数按当前导入全部记录统计，不随搜索或筛选变化。超过 6 次仍显示，并可从列表查看。

铁路拟合
默认按日期及车次查询 RailLog 历史快照，选取不晚于行程日期的最近版本，截取乘坐区间，再按停站顺序沿 OSM 轨道寻路。
快照仅作参考，不保证当日实际开行及唯一实际径路；两停站间仍使用 OSM 路网推算。
没有可用快照时标注为网络推算。路路通尚未接入自动接口；经路路通人工核对的中间站可填入“人工途经站”，用分号分隔。
同名站结合起终点、承运方及位置自动匹配。支持手动坐标，格式为“纬度,经度”。
轨道不连通时显示错误，不画直线替代。连续区间共享真实轨道节点，不以直线跨接。
单段直线距离超过 900 km 时需提供更多途经站。
OSM 当前路网不等同于 2019 等历史年份的铁路网络，旧线路变化仍可能影响拟合。

数据与隐私
表格在浏览器中处理，不整体上传。刷新后当前记录会丢失，请导出 GeoJSON 保存生成的轨迹。
站名及铁路查询范围发送到 Overpass，机场坐标在本站数据中读取；车次和时刻表快照版本发送到 RailLog。
OSM 地图及轨道：OpenStreetMap，底图提供方 OpenFreeMap；地形阴影：Mapzen DEM。
时刻表文档：https://www.raillog.top/api-docs/timetable.html

验证状态
已通过年度 Sheet、完整日期、闰年和异常日期、倒序、单表/多表、原始行号、铁路 6/7 次边界、航线错开及详情卡片测试。
已实测 RailLog 版本及 G1 停站接口，测试了区间截取、方向校验和异常记录拒绝。
真实铁路测试使用 OSM API 下载的新宿—代々木数据：30 个节点、约 723 米，逐条路径边均在实际 OSM 铁路上。
已在浏览器查看真实轨迹；中国铁路完整在线行程尚未完成端到端验证，公共 Overpass 仍可能拒绝请求或超时。

## 2026-11-26 生成与数据修复

航班读取本站机场坐标库，不再查询 Overpass。坐标来自 OurAirports 公共领域数据：https://ourairports.com/data/ ，2026-11-26 获取。航线弧高为端点投影距离的 1.5%—6%，单次 4%。
OSM 单服务限时 15 秒，失败后切换，失败服务冷却 30 秒；成功结果在 IndexedDB 缓存 30 天。铁路仍需要可访问的公共 OSM 服务，502 不会被伪装为有效线路。
日期单元格中的完整年份优先于 Sheet 年份；铁路需有效完整日期（年份可由 Sheet 补全）；航空日期可空。
腐败率即每公里单价，优先使用表内值，否则由价格/里程计算，保留原始正负号。
车站结合原始名称、中文/日文别名、承运方、起终站上下文和位置自动匹配。判断属于启发式，不保证所有同名站及复杂换乘均唯一正确。
历史快照按车次与版本持久缓存，不用当前表覆盖旧表。按钮“缓存导入车次的历年时刻表”会为导入车次缓存 2019 年至今各年最新可用快照及行程日期对应快照，并报告空记录和失败；这不是历年全部列车全日期数据库。

镜像调度：接入 OSM Wiki 列出的三个全球数据提供方（VK Maps、Private.coffee、FOSSGIS）。未冷却的节点轮流分担查询；失败按 30/60/120 秒递增冷却，最多 5 分钟。相同查询共享请求与缓存，不向多个节点重复广播。英国/瑞士等区域实例不用于中日行程，旧 kumi 域名与 private.coffee 为同一服务，不作为独立镜像重复计数。

铁路请求简化：车站按整条行程合并查询；同区间/途经站/历史版本/运营方的成功轨迹缓存 30 天；100 km 内多途经站共用一次铁路网络下载，在浏览器内分段寻路。更长行程仍按停站区间查询，以避免一次下载过大。


## 独立铁路寻路（2026-11-26 更新）

默认流程不再依赖 Overpass：OpenRailwayMap 车站索引 → BRouter rail profile → 轨道标签与站点校验 → 缓存。历史停站或人工途经站作为同一次寻路请求的按序途经点，不把独立结果用直线拼接。Overpass 本地建图保留为手动选择的备用模式。

浏览器实测：新桥—上野、嘉兴南—上海南、琶洲—白云机场东、京成上野—成田空港四条全部生成；当前版本按新要求校验铁路日期。实测新桥—上野为 137 个坐标点、约 6.438 km；嘉兴南—上海南为 405 个坐标点、约 80.073 km。两条响应的 WayTags 均为 railway=rail。

校验拒绝非铁路标签、距输入起终站超过 1 km 的吸附，检查途经站。结果仍是当前 OSM 网络推算，不证明历史列车真实径路；站点中心与股道可能有偏移。

第三方服务独立于 Overpass，但仍可能限流或缺少连接数据。站点查询限时 5 秒，遇 429 停止并冷却；成功结果缓存，不预取无关车站。

站名发送至 api.openrailwaymap.org，途经坐标发送至 brouter.de，不上传完整表格。
数据：OpenStreetMap contributors (ODbL)；站点服务：https://www.openrailwaymap.org/ ；铁路寻路：https://brouter.de/ 。
修改后运行 node scripts/build.mjs，使用内容哈希应用包，避免混用依赖。


2026-11-27 修复：
- 国铁车次使用仅允许 railway=rail 的 BRouter 自定义规则，避免大站吸附到地铁网络。默认 rail 规则包含 subway；杭州东—嘉兴南实际复现 HTTP 400/no track found，国铁规则对照请求成功。
- 按相邻停站独立计算并缓存区间，站内允许换向；仅在真实共享轨道坐标处拼接，不用直线补缺口。G7402/G7408 的 2026.11.20 公开快照全程通过真实接口和拼接校验，另验证杭州东—嘉兴南、广州南—深圳北、长沙南—广州南及潮汕—杭州东。停站约束仍不能代替当日实际运行线路证明。
- 每个服务串行且设请求间隔；HTTP 错误显示服务、状态和响应摘要。403/429 停止该服务，遵守 Retry-After，并保存冷却状态。没有通过大量请求主动触发封禁；本次不能从旧版截图确认此前 403 的具体来源。公共服务不保证大规模生成可用，持续被拒绝需联系服务方或使用自建服务，不通过更换 IP/伪造标头规避。
- 全部、勾选、铁路、航空四种生成范围；已完成行程直接复用。取消勾选隐藏轨迹，重新勾选恢复，不删除路径。全选/全不选作用于当前导入的全部记录；搜索筛选不修改选择。点击记录正文仍可查看详情。
- 飞行线为高亮银白色 #fbfdff、2.2 px，配深色描边，适应浅色底图。

日历与必填校验（2026-11-27）：
- 中国国铁：有效出发日期、车次、精确出发/到达站名必填。日本铁路：有效日期和精确起终站名必填，车次可空。航空：起终机场三字码及航班号必填，日期可空。
- 「日期」与「出发日期」、「班次」与「车次／航班号」列名均支持；完整日期优先使用其自身年份，年度 Sheet 可补年月日中的年份。缺少字段的记录保留并标红，在详情中可直接修正，不发起该行的寻路请求。
- 日历默认展示最近的有行程月份，可直接选择其他有行程月份。无行程日期禁用。日期筛选与搜索、交通方式筛选叠加，同时控制列表、地图、详情卡片、导出及生成范围；全选/全不选仍作用于全部已导入记录。恢复全部日期不会改变勾选状态或丢失已生成路径。
- 跨日优先级：显式「到达日期」→ 到达时间 +1/+2/次日/翌日 → 已查到的历史停站表 → 到达时刻早于出发时刻推定次日。覆盖的每个日期均显示该行程，包括跨年与闰日。不提前批量请求时刻表；生成后获得跨日信息会自动更新日历。
- 航空跨时区应填写到达日期；仅靠当地时钟不能可靠判断日界线。无日期航空可用「无日期行程」查看。无法确定跨日时暂按出发日显示；异常到达日期提示核对。单条跨度超过 366 天视为异常，避免错误输入生成巨量日历格。
- 实测分类依赖车次、站名、承运及 Sheet 的地区线索；同名站仍需以实际站点匹配结果核对，不能用一个站名保证全球唯一性。

GitHub 全国铁路时刻表缓存（2026-11-27）：
- 不按用户导入车次限量。scripts/cache-timetables.py 枚举 RailRhythm12306 的全部 train_list 文件，以及 chinese-railway-gtfs 全部分页 Releases 中的 GTFS 文件，保存每份文件的全部可用车次。
- 当前可批量取得的是 2025、2026 年快照；2019–2024 尚未取得批量文件。RailLog 的全历史数据库存放在上游私有仓库，公开接口只提供逐车次查询，不能把版本目录当成已经缓存的数据。旧年份仍使用公开接口按需查询并存入浏览器。
- 数据保存在 dist/data/timetables/，不是只存于浏览器。index.json 记录源文件 URL、快照日期、车次号数量、实际时刻记录数及 SHA-256。压缩文件按内容散列去重，重复车站、途中换号、跨日时间和多种停站方案保留。GTFS 虚拟线路车次被剔除。各快照里的车次号数量包含途中换号，不能直接相加作为全国唯一车次数。
- 生成时先检查本站快照，只有所选快照不早于已知的其他适用快照才采用，避免拿更旧缓存覆盖新运行图；无匹配时继续查询 RailLog。不会把未来快照套到过去的行程。同一方案可匹配多个换号车次；歧义方案要求核对时刻或途经站。
- 页面「查看本站时刻表缓存」显示实际覆盖与缺失年份。「下载导入车次到本机」仍是浏览器中的按需缓存，二者分开说明。
- 补充所有新公开文件：python scripts/cache-timetables.py，然后 python scripts/verify-timetables.py。已完成文件可断点续用；错误写入清单，脚本失败退出，不能发布为完整缓存。数据只有事实字段，来源及 CC BY 4.0 署名见 dist/data/SOURCES.txt。
- GitHub Actions 首次部署会构建并验证全部缓存，再提交数据到 main 和发布 Pages；手动运行 Check and deploy GitHub Pages 可刷新全部公开源。没有定时任务，不会持续高频请求上游。
- 运行环境：现代 Chrome/Edge/Firefox/Safari，需支持 DecompressionStream 和 Web Crypto；本机通过 start.cmd 的 localhost 服务打开。浏览器无法读取压缩缓存时回退公开接口。
